# 抵押品系统

Isometric 的抵押品系统旨在实现最高水平的安全性和透明度。作为备兑看涨期权协议，每份期权合约在创建时都必须由实际资产提供 **100% 抵押**。

## 抵押品类型

当前版本中，Isometric 使用 **ckBTC** 作为唯一的抵押品形式。通过 ckBTC 实现原生比特币抵押，可确保抵押品资产与标的资产的价格变动是镜像关系，从而消除了卖方的美元计价爆仓风险。

## 备兑看涨期权逻辑

在 Isometric 上，"Covered"（备兑）意味着：
- 卖方必须在合约开始前锁定 1.0 BTC 的抵押品，以支撑 1.0 BTC 数量的期权。
- 该抵押品将被托管在智能合约中，直至到期或手动取消挂单。

## 生命周期中的抵押品状态

### 1. 挂单状态 (Offer State)
当卖方创建挂单但尚未被接受时，系统会检查其**可用余额**。虽然此时资产尚未从其余额中移除，但如果余额不足，买方将无法接受该挂单。

### 2. 锁定状态 (Locked State)
一旦买方接受报价，抵押品即被正式从卖方的账户转移到**平台锁定账户**：
- 卖方无法提取这部分资金。
- 资金无法被再次用于其他订单。
- 这确保了到期时无论价格如何波动，买方的潜在收益始终有资产保证。

### 3. 结算与释放 (Settlement & Release)
到期结算后：
- 如果期权为虚值 (OTM)，全部抵押品归还给卖方。
- 如果期权为实值 (ITM)，根据计算，部分抵押品转给买方，余额退还给卖方。

## 安全性保障

### 非托管设计
抵押品由智能合约逻辑控制。没有中心化实体可以挪用锁定中的抵押品。所有资金变动都由链上账本记录，且必须符合预定的合约条款。

### 自动解锁
系统不依赖于管理员手动操作来释放抵押品。只要预言机确定了到期价格，结算逻辑就会在同一个交易批次中完成资金分配。

## 开发者视角

容器代码中使用账户抽象来隔离锁定资金：

```rust
pub struct CollateralPosition {
    pub owner: Principal,
    pub amount: u64,           // 以聪为单位
    pub option_id: OptionId,   // 关联的期权 ID
    pub expiry: u64,           // 到期时间戳
}
```
