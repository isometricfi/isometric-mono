# 合约标准化

Isometric 使用**标准化期权合约**，而不是允许用户输入任意条款。这种设计选择对于在去中心化挂单簿中建立流动性至关重要。

## 为何需要标准化？

1. **流动性聚合**：将买卖双方集中在少量的“行权价”和“到期日”组合中，防止市场过于碎片化。
2. **易于定价**：对买卖双方来说，对比和选择合约变得更加直观。
3. **合约参数匹配**：标准化使得多个买方可以更容易地购买同一个大额卖方订单的部分颗粒（部分成交）。

## 核心参数规范

### 行权价百分比 (Strike Percentage)

行权价不在订单创建时以美元固定，而是以“当前市价之上的溢价百分比”来定义。当订单被接受时，系统捕获瞬时价格并锁定确切的美元行权价。

**常见行权价选项**：
- **+5%**：略微价外，权利金较高。
- **+10%**：中度价外，平衡了风险与收益。
- **+15%**：深度价外，适合只想赚取极少量额外收益的保守派。

### 标准化到期时间 (Standardized Durations)

所有期权都遵循固定的周期性到期时间。这种时间窗设计可以使活跃用户在每个周期结束前进行批量操作。

**支持的期限**：
- **1 Day** (每日合约)
- **7 Days** (每周合约)
- **14 Days** (双周合约)

### 权利金百分比 (Premium Percentage)

权利金统一以“抵押品金额的百分比”报价。

**标准权利金级分**：
- **0.5%**
- **1.0%**
- **2.0%**
- **5.0%**

## 最小成交粒度

为了确保网络效率并考虑到 ckBTC 的转账费用，系统设定了最小成交金额（例如 0.001 BTC）。低于此数量的订单接受请求将被系统拒绝。

## 未来扩展

虽然当前的标准化系统是静态的，但未来可能会过渡到：
- **治理调整**：由代币持有者投票决定增加新的行权价或到期间隔。
- **自适应标准化**：根据市场波动性自动调整支持的行权价范围。
