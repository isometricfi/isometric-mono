# 结算机制

结算（Settlement）是 Isometric 期权生命周期中最关键的阶段。我们的结算流程被设计为**全自动**、**不可变**且**基于预言机**，以确保所有参与者的公平性。

## 结算类型：现金结算 (Cash Settlement)

Isometric 采用**现金结算**（以 BTC 支付差价），而非物理交割。
这意味着：
- 期权到期时，卖方无需真的卖出 BTC，买方也无需支付全款买入 BTC。
- 只有期权的**内含价值 (Intrinsic Value)** 被计算并从卖方的抵押品转给买方。
- 所有的价值交换都是比特币 (ckBTC) 到比特币。

## 结算公式

Isometric 的结算计算考虑了以美元计价的行权价，但最终以 BTC 支付给用户。

### 内含价值 (美元计价)
**V_usd = max(0, P_expiry - Strike)**
其中 **P_expiry** 是预言机提供的到期时刻 BTC 价格。

### 赔付金额 (BTC 计价)
**Payout_btc = (V_usd / P_expiry) * Quantity**

**简化后：**
**Payout_btc = ((P_expiry - Strike) / P_expiry) * Quantity**

### 示例计算
假设：
- 行权价 (Strike): $100,000
- 到期价格 (P_expiry): $120,000
- 订单数量 (Quantity): 1.0 BTC

**计算：**
1. 差价 = $120,000 - $100,000 = $20,000
2. 收益占到期价格的比例 = $20,000 / $120,000 = 1/6 (约 16.67%)
3. 买方可获得 0.1667 BTC

买方获得 0.1667 BTC，卖方拿回剩余的 0.8333 BTC + 预先赚取的权利金。

## 自动化流程

1. **到期触发**：到期时间一到，系统全局定时器介入。
2. **调取预言机**：容器向汇率分片（Exchange Rate Canister）发出异步请求，获取过去一分钟内的平均成交价格。
3. **计算与分派**：
   - 检查期权是否为实值 (ITM)。
   - 如果是，计算赔付额并转移资金。
   - 如果是虚值 (OTM)，资金原路返回给卖方。
4. **状态更新**：期权在数据库和前端展示中标记为“已结算”。

## 费用扣除

在赔付过程中，系统会自动从买方的所得收益中扣除 20% 的**利润费 (Profit Fee)**。

详见 [费用详情](/architecture/fees)。

## 结算异常处理

如果遇到极端的预言机故障或网络问题：
- **重试机制**：系统会在 10 分钟后自动重试价格请求。
- **安全锁**：如果预言机返回的数据被标记为不可信，结算将暂停，直到管理员介入或价格恢复正常，保护用户资产不受错误定价的影响。
